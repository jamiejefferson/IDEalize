# Agent Note: The tab row goes, and the space seeds the view

Status: implemented

Part of the spaces-and-brains reshape, after [Trajectory as a rail pane](2026-08-26-trajectory-as-a-rail-pane.md) and [Schedule returns to the rail](2026-08-27-schedule-returns-to-the-rail.md). The tab row is upstream `@deepseek-ai/dsh-client-ui-conversation`'s; the seed is `@idealize/ui-bar`'s; the space is `@idealize/spaces`'s ([vocabulary](../architecture/2026-08-26-idealize-spaces-vocabulary.md)).

## Problem

The conversation header rendered a `role="tablist"` whenever the view ring held more than one entry, and each tab wrote the chat store's `view`. Once Trajectory and Schedule left for the rail, every remaining entry was a space: Chat, Gallery, Sound Stage, and Terminal on the desktop. The space is fixed for the life of a chat — its tools are the space's, and a started chat's preset is host-locked — so a visible tab row was a control for changing something the product says cannot change. JJ settled the direction on 26 Aug: "100% agree. move them both out of the tab bar. move both to the rail."

Deleting the row exposed what it had been doing besides offering a choice. It was the only visible thing that ever put a chat onto its view, and the chat store persists `view` in `localStorage`, so a reload with that storage cleared, or on another machine, landed every chat on Chat: a Gallery chat came back as a chat with no gallery and a composer with no aspect dock. The durable record (`idealize/space`, projected as `space`) said Gallery; nothing read it.

The block could not be removed from a plugin. The tablist rendered unconditionally on `tabs.length > 1`, its classes are hashed CSS-module names, and the header component is a fixed occupant with no seat for a replacement.

## Decision

**Delete the tablist from `ConversationSession.tsx`, and with it the header's non-chat exemption.** The header hid on a blank chat only while the active view was Chat; a blank Terminal or Gallery chat kept the header because "the ring tabs are the way back to Chat". With no tabs, that exemption had nothing to keep, so the header now hides on every blank chat and the view fills the column under it exactly as the hero would. `data-blank-view` still carries the active view's id, and the terminal still retires the composer seat by matching on it. `resolveActiveView`'s Chat fallback stays: a persisted id for a view the ring no longer serves still lands on Chat rather than nothing. The `.tabs`/`.tab`/`.tabActive` rules leave the stylesheet.

**`@idealize/ui-bar` seeds `view` from the `space` projection**, in `view-switch.ts` beside the inspect handoff, through the same `hostFace().storeOf` instance the rendered ring reads. The seed runs once per chat per page, the first time that chat is current and its projection, the chat ring entry and the store instance all exist; a space whose view the ring does not serve (Motion everywhere, Terminal in a plain browser) lands on Chat and stays eligible in case that view registers later. Once per chat is the point: the welcome card's launch writes the same store after the seed, and a seed that re-fired on every list change would fight it. Four of the five space ids equal the ring entry id that renders them, so no translation table exists; the fifth, Motion, has no view.

**The welcome card retires on a recorded brain, not only on an in-memory launch.** `HeroLauncher` kept its launched state keyed to the session in React state, so a reload forgot it and asked "Which space are we working in?" again inside a chat that already had one. Before this change the reload also forgot the view, so the card came back over the hero and nobody noticed; with the seed landing the chat on Gallery, the chooser rendered inside the Gallery composer. `currentSession()` now carries the `brain` projection, and the card counts a chat with a recorded brain as launched. Only a launch or a brain switch appends `idealize/brain`, so a fresh blank chat still asks.

**The proofs that clicked or counted tabs change with it.** `schedule-proof.mts` asserted the ring rendered at least one tab so its "no Schedule tab" meant something; it now asserts zero. `welcome-spaces-proof.mts` reads the landed view off `data-blank-view` instead of `aria-selected`. `brain-switcher-proof.mts` (the packaged-window S4 proof) flipped Chat⇄Terminal through the tabs to start a Terminal chat; it now presses ui-terminal's ⌘J shortcut, the one remaining view switch, in both directions.

## Alternatives considered

- **Hide the row with CSS from `@idealize/ui-bar`.** The class is hashed; the only selector left is `[role="tablist"]` inside the header, which would also hide any future tablist a header occupant renders, and the buttons would stay in the accessibility tree. Rejected.
- **Seed the view from upstream `ConversationSession` on session bind.** Upstream would have to know the `space` projection, a fork concept, and the fix would sit in a file the fork already touches for `data-blank-view`. The client runtime already publishes `projectionValues.space` on every `SessionSummary`, and ui-bar already holds the store resolver, so the seed needed no new seam.
- **Seed on every list change, not once.** Simpler, but the welcome card launches by writing `view` after the space POST, and the projection arrives a beat later; a seed that re-fired would flip a just-launched chat back to the derived space and then forward again. Once per chat per page, retried only while the ring cannot yet serve the space, has no such window.
- **Delete ui-terminal's ⌘J shortcut in the same change.** It is the one control left that moves a chat between Chat and Terminal, so it contradicts the fixed space as much as the tabs did. It lives in `@idealize/ui-terminal`, whose packaged-window proof cannot run headless (there is no embedded terminal in a browser), and the S4 proof needs a way to start a Terminal chat. Left in place and named here so the decision is taken on purpose, not by omission.

## Consequences

The header is title row plus two action seats; `ConversationSessionHeader` no longer reads the views ledger or the chat store. The ui-terminal `ModeShortcut` occupant of `conversation.session.header.actions` therefore mounts only on a started chat, so ⌘J is inert while a chat is blank. Nothing else in the shell offers a view switch: the ring's active view is written by the welcome card's launch, ui-terminal's `terminalMode.open`/`restart`, and the space seed.

Both open items named below were closed on 28 Aug — see [the launch names its brain, and New chat mints a chat](../bug-fix/2026-08-28-launch-names-its-brain-and-new-chat-mints-one.md).

Two things this exposes are left standing and named here. The host's "New chat" reuses a workspace's blank chat rather than minting one (`SessionSummary.blank`, `api-proxy.ts`), and a chat launched into Gallery or Sound Stage stays blank until its first turn; with the tab row gone and the card retired on its record, pressing New chat from such a chat shows that same Gallery or Sound Stage view again and offers no chooser until a message is sent or another chat is opened. The right fix is for a launched blank chat not to count as reusable, which is a host-side `blank` question outside this slice. And ui-terminal's ⌘J still flips Chat⇄Terminal on a started desktop chat, as recorded under Alternatives.

A chat's space is durable rather than remembered: `packages/idealize/spaces/proof/tab-row-gone-proof.mts` reloads a Gallery chat after `localStorage.clear()` and requires the Gallery view and its aspect and count dock back, in both themes. The same run enumerates every `[role="tab"]` and `[role="tablist"]` in the session header of a chat in each space and requires zero, and requires the chooser absent from the reloaded chat. Terminal in that run is what headless can honestly show: a plain browser serves no embedded terminal and the card refuses Terminal as `desktop-only`, so the run records the space on a started chat through `POST /idealize/spaces/select`, and after the reload the sidebar row carries the Terminal glyph while the seed's own rule lands the chat on Chat with its composer; the shell itself is the packaged-window proof's evidence.
