# Agent Note: JJ's 8 Sep review — every provider carries its company's name, a long model list takes a filter, and the Budget tab prices what it can from three sources and reports what fal billed

Status: implemented

JJ, 8 Sep 2026, on the landing-12 build: "Brains: model choice for Writing — OpenAI listings are different to others and are listed as gpt rather than OpenAI; make consistent. Also gpt 6 is not available." and "Cost of the models has not been included in the budget section." Reviewing the Budget tab that first pass produced, JJ asked: "what about Fal? and also the subscription models?"

## Problem

`GET /idealize/models/state` served each route's `displayName` as `llm-pi-ai` declares it, which for a catalogue route is the route id (`declare(provider, provider)`), so the edit sheet's picker grouped OpenAI's models under `openai` beside `Free tokens` and `OpenAI (ChatGPT)`. The pane had two naming paths: `providerName()` title-cased an id for the Subscriptions rows, while `providerLabel()` printed the payload field verbatim for the picker groups. The picker itself was one `<select>` over every provider's catalogue with no way to narrow it; the free engine alone registers every model its sidecar reports. `gpt-6` is in no catalogue the app reads: the OpenAI list is pi-ai 0.82.1's built-in catalogue (38 models, `gpt-4` through `gpt-5.6-terra`, `o1` through `o4-mini`), and nothing on screen said where a list came from or when it was read. On cost, `pricing.ts` could turn tokens into money but only from `ModelsConfig.tokenPrices`, which no route wrote and no surface edited, so the Budget tab showed the "set prices in settings" hint and no per-model figure. The tab also measured tokens alone. Every generated image or clip goes through fal, which bills per unit produced and publishes a usage report this app never read, so a month of generating showed as no spend at all.

## Decision

**One naming rule, applied at the source and once more at the edge.** The state route resolves `displayName` through `serviceName()` from `@idealize/services` (`@idealize/models` gains the dependency), so `openai` reads OpenAI and `openrouter` OpenRouter wherever the payload lands. The pane's `providerDisplayName(id, displayName)` is the one function behind picker groups, Subscriptions rows, access notes and budget notes: the directory's name when it differs from the id, else the id with a capital. Providers sort by the name as shown.

**A filter over a long catalogue, and a note that says what the catalogue is.** Past 40 models (`MODEL_FILTER_FROM`) the sheet renders a search field above the select; a query narrows every group by model id or provider name and drops empty groups. A note under the select reads "412 models from 31 services, read 8 Sept, 10:12. A model a service has not published yet is not listed." and, when the filter matches nothing, "No model matches “gpt-6”." with the same sentence after it. The state payload carries `readAt` and each provider's `catalogue` (`built-in` from the app's shipped catalogue via `declared !== true`, `configured` from the route's own settings). No model is added by hand; the note is the explanation.

**Three price sources, each marked, ranked by how close it is to the person.** `src/prices.ts` reads OpenRouter's `/api/v1/models` payload (`pricing.prompt` and `pricing.completion`, USD per token as strings) into per-million `TokenPrice`s, taking `input_cache_read` and `input_cache_write` where published and the prompt price where not, which is what a model with no cache discount charges. The list is cached at `<home>/service-catalogues/openrouter-prices.json` with `fetchedAt`, beside the media catalogues, and refreshed by the usage route after `openRouterPriceRefreshMinutes` (default 1440, 0 never fetches) while the `openrouter` route has a stored key and `currency` is `USD`. Beneath it sits the catalogue the app ships: `shippedTokenPrices` in `@idealize/services` reads pi-ai's published per-model `cost`, dropping an all-zero or negative row, and the usage route builds that table for every chat route the `llm-pi-ai` settings section holds a profile for while `currency` is `SHIPPED_PRICE_CURRENCY` (`USD`). `effectivePrices(user, openRouter, shipped)` lays catalogue, then OpenRouter, then the person's `tokenPrices`, every entry marked `source: 'user' | 'openrouter' | 'catalogue'`. `POST /idealize/models/prices` stores one model's price through `parsePriceBody`, which refuses a body missing any of the four kinds rather than reading it as free, and clears an entry on `price: null` through `settings.mutate`.

**The Budget tab shows each model's cost.** The usage payload gains `models` (`modelRows`: one row per model with usage this month, by token total, with `cost` and its `price` where a metered route has one) and `openRouterPrices` (`fetchedAt`, model count). The pane renders a Models this month table: tokens per row; a cost and Edit price for a priced metered row, a dash and Set price for an unpriced one, the category word for subscription and free rows. The action opens an inline editor for input and output per million, cache read and write under Cache prices (blank takes the input price), Enter or Save posting to the prices route and re-reading usage; an OpenRouter-priced row's editor says "Price published by OpenRouter, read 8 Sept, 07:24. A price you type replaces it." The total sums the priced rows and says "1 unpriced". A catalogue-priced row's editor says "Price from the model catalogue the app ships. A price you type replaces it."

**What a generation cost comes from fal's own bill, and what was generated comes from the session log.** `src/generations.ts` folds `artefact/created` events per `provenance.provider` and `provenance.model` into month-to-date and year-to-date counts in the same `sessionLogs()` pass that folds tokens, under the same project scope. With a key stored for the `fal` media backend — the credential `@idealize/services` registers it with, read back through the generation runtime's `credentials()` — the route reads `GET https://api.fal.ai/v1/models/usage` with `Authorization: Key <key>`, `timeframe=month` and `expand=time_series`, follows `next_cursor`, and files each bucket's `endpoint_id` / `unit` / `quantity` / `cost_total` / `currency` under its calendar month. That report is cached at `<home>/service-catalogues/fal-usage.json` with `fetchedAt` and re-read after `falUsageRefreshMinutes` (default 1440, 0 never fetches). The payload gains `generations` (`rows`, the per-currency `billed` totals, the `currency` fal billed in) and `falUsage` (`fetchedAt`, any `error`). The pane's Generations this month table lists one row per endpoint, carrying the count and media kind beside fal's figure; a row fal has not billed reads "not billed yet", no stored key reads "Connect fal to see what generations cost.", an empty month reads "No generations this month.", and a refused read shows fal's own message. Nothing estimates a generation's price.

## Alternatives considered

**pi-ai's `cost` fields as the only price table.** The first pass refused them outright as figures frozen at packaging time. They are still that, which is why they rank below both live sources and carry a `catalogue` mark the editor states. Refusing them entirely left every metered route unpriced until the person typed a rate, and a stale published figure marked as such tells JJ more than a blank does.

**A typed price per generation endpoint.** The price editor could take a per-image rate the way it takes a per-million token rate. fal's own bill already carries the figure with its discounts applied, and a typed rate would compete with it and quietly win on rows fal had not yet reported.

**Adding `gpt-6` to the OpenAI route by hand.** No catalogue the app reads lists it; a hand-written id would resolve to a request OpenAI refuses, and the fix JJ needs is knowing why a model is absent.

**Importing `@idealize/services` into the client for the names.** The package is host-side (`dsh-home-paths`, pi-ai); the client bundle is platform `web`. Resolving at the state route keeps the client dependency-free and every consumer of the payload consistent.

## Consequences

A route the services directory does not know still reads as its id with a capital (`Mutter`, `Kimi-coding`); adding it to `SERVICE_NAMES` fixes every surface at once. Both automatic price sources apply in USD only, so another `currency` leaves every route to the person's entries. Prices are current figures: a refresh or an edit reprices the whole month, and no history is stored to reprice from. A metered route now shows a cost as soon as the catalogue prices it, which flips `cost.configured` to true earlier and replaces the "set prices" hint with figures the person did not type — the editor names the source for exactly that reason.

Generation spend is fal's alone. Another media backend contributes a count and no figure, and the usage route reads fal on the same request that folds the logs, so a slow or refused read delays the Budget tab by that request's timeout (15 seconds) unless the cache is fresh. Tests: `models/tests/generations.spec.ts` (the local fold's month and year boundaries, records without provenance, the two-page reader over fal's published `time_series` shape with a malformed item skipped, the cache round trip and its wrong-year and truncated cases, refresh over a fresh cache, a stale cache, zero minutes, an HTTP refusal and a thrown fetch, and the row merge and sort), `models/tests/prices.spec.ts` (three-source precedence beside the earlier directory, cache and validation coverage), `models/tests/routes.host.spec.ts` (the usage payload with a stored fal key and an injected fetch, without a key, with no runtime naming the credential, with fal refusing, and the catalogue pricing a profiled route), `models/tests/pricing.spec.ts` (`modelRows` over mixed priced, unpriced, subscription and free rows), `ui-bar/tests/brains-panel.client.spec.tsx` (label resolution across picker and Subscriptions, filter and no-match note, the per-model table and a price commit, refusal of an incomplete price, the generations table's four states, and the catalogue price source).
