# Agent Note: JJ's 8 Sep media review — the details column scrolls, a video tile is a preview, tiles rest bare, a message shows as a turn, and a picture can seed a video

Status: implemented

JJ, 8 Sep 2026, on the landing build: "Image view, right hand column doesn't scroll so the bottom of the prompt and actions are cropped"; "The expanded view on video is not working. Also the 3-dot nav is not styled or positioned correctly"; "Gallery design is ugly - use bigger images and hide ui elements on assets until hover"; "In the image, sound and video sections, when you post a message it looks like it's not working. It would be good if the layout was more like a chat with the prompt visible and then some sort of indicator that its working on it"; "I tried to use an image created by another agent as a reference when creating a video but it's not working."

## Problem

The enlarged view's body was a two-column grid with `max-height: 100%` and no row track, and its details column had `overflow-y: auto` with no `min-height: 0`; a grid item's minimum height is its content, so the column grew past the sheet and the sheet clipped it. The video tile rendered a native `<video controls>` inside the button that opens the enlarged view: play, scrub and the browser's overflow menu all bubbled to the button, and the menu drew wherever the browser put it over a 240px tile. Tiles held their Reveal, Keep and Archive buttons at `opacity: 0`, which hides nothing from hit-testing, on a 240px grid with `object-fit: contain`. The `gallery` projection started a row only at a generation `tool/call`, so between sending a message and the model's tool call the grid showed nothing, and a turn in which the model asked a question instead of generating showed nothing forever. `generate_video` had no parameter for a source picture, `GenerationRequest.attachments` was never populated, and the fal queue adapter posted every video request to the catalogue's `text-to-video` endpoint, which takes no `image_url`.

## Decision

**The details column scrolls inside the sheet.** `.enlargedBody` declares `grid-template-rows: minmax(0, 1fr)`, `.details` declares `min-height: 0`, and the actions stay in that column, so the column is what shrinks and scrolls. **A video tile is a silent preview.** The tile's `<video>` is muted with no controls behind a play glyph; the enlarged view renders `<video controls autoplay>` sized to the well (`max-height: 80vh`, width auto), and the sheet's body stops propagation, so a click on the player stays inside. The native overflow menu therefore appears only in the enlarged view. **Tiles rest bare.** The grid is `minmax(320px, 1fr)` with a 16px gap (the archived fold `200px`), the media covers a 4:3 frame (`object-fit: cover`, chosen over the picture's own aspect because a grid of full frames reads as one piece and the enlarged view shows the whole picture), and the corner controls rest at `visibility: hidden; pointer-events: none`, returning on `:hover` and `:focus-within` and staying on under `@media (hover: none)`. The Sound Stage rows take the same rule. **A message shows as a turn.** Two Definitions join the generation one in `@idealize/ui-gallery`: `gallery-turn`, one Context per turn, opens `thinking` at `turn/start`, moves to `generating` at a generation `tool/call`, keeps the model's last text from `assistant/message`, and settles `generated` or `no-generation` at `turn/end`; `gallery-prompt`, one Context per user-sourced `user/message`, carries the text and log position. A `user/message` carries no turn number and a Definition's `match` sees only the event, so the target's builder joins each prompt to the turn whose `turn/start` precedes it. Images, Video and the Sound Stage render a chat-like row for a turn still thinking (prompt, spinner, "Thinking…"), for a running generation ("Generating…"), and for a turn that made nothing (the model's reply, or "Nothing was generated this turn." / "Stopped."); the tile takes the row's place. **A picture can seed a video.** `generate_video` and `generate_image` take `reference_image`: an artefact id resolved through `ctx.artefacts` whatever chat made it, or a path under the project, judged on real paths so a project reached through a symlink admits its own files and a symlink pointing out does not. The bytes go into `GenerationRequest.attachments`; the artefact record keeps the reference as `reference_image`, the provider never sees it as a setting. The fal queue adapter's `endpointFor` sends a request carrying an image to the `image-to-video` sibling of a `text-to-video` endpoint and reads that endpoint's schema.

## Alternatives considered

**Fold the prompt into the turn Definition through Location data.** The upstream chat's `message` Definition publishes no turn data carrying the text, and a `buildLocationData` publisher plus a dependent reader is two more moving parts for one join the builder does in six lines.

**One Definition keyed by turn matching `user/message`.** Its `match` has no history and the event carries no turn number, so the id cannot be produced.

**Wire the seam's progress sink so the row shows the queue position.** It needs a new `SessionEventMap` member and a doc-sync update; the spinner answers the report, and the README lists the sink as deferred.

**Keep the video's native player on the tile with `stopPropagation`.** The overflow menu still draws over a 320px tile, and a tile that both plays and opens has two meanings for one click.

## Consequences

The 'video plays in the tile' test changes with the behaviour: the tile asserts a muted preview with no controls and a glyph, and the enlarged view asserts `controls` and `autoplay`. jsdom lays nothing out, so the scroll and hover contracts are asserted against the stylesheet text and the DOM structure; the packaged walk owns the layout. Walk checks for `landing-walk-proof.mjs`: open an image tile at 1280x840, confirm `[data-gallery-details]` has `scrollHeight >= clientHeight` and `[data-gallery-close]` is within the sheet's bounding box after scrolling the column to its end; on the Video landing confirm `[data-gallery-video]` inside `[data-gallery-open]` has no `controls`, that clicking `[data-gallery-open]` yields `[data-gallery-player][controls]` inside `[data-gallery-enlarged]`, and that clicking the player leaves the sheet open; confirm `getComputedStyle('[data-gallery-actions]').visibility === 'hidden'` at rest and `'visible'` after hovering the tile, and that the grid's first tile is at least 320px wide; send a message on Images, Video and Sounds and confirm `[data-gallery-turn="thinking"]` (or `[data-soundstage-turn="thinking"]`) carries the typed prompt within a second, then that it is replaced by `[data-gallery-tile="running"]` or a done tile; on a chat where the model answers with text, confirm `[data-gallery-turn="no-generation"] [data-gallery-reply]` carries that text; on Video, ask for a clip from an Images artefact id and confirm the tool call carries `reference_image` and the fal request URL ends in `image-to-video`.
