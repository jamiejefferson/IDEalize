# Agent Note: JJ's 8 Sep review of the minimode bar — it drags and remembers its place, the Studio leads with an owl, it shows the sidebar's agents, and it wears the sidebar's colours

Status: implemented

JJ, 8 Sep 2026, on the landing build: "Minimode bar is not draggable and often appears in the middle of the screen"; "Minimode bar - group chat - change to Studio and place at the top to match the full view order. Also use a small owl instead of the black square"; "The agents that appear here bear no relation to the ones in the desktop view"; "Minimode bar design: the background should match the sidebar background, with the logo appearing exactly as on the desktop view."

## Problem

The Askbar window (`dsh-plugin-desktop/src/askbar-window.ts`) was created `movable: false` with no drag region in the bar's CSS, and it placed itself in a `show` listener, after the window had painted; the deferred first show (a collapse before `ready-to-show`) showed without placing at all, so macOS's cascade left the bar mid-screen until the listener ran, and nothing persisted where the user might have wanted it. The bar's foot was a `Group chat` button with a literal `@` in a black 36px square, last in the column, while the main sidebar leads with a pinned card titled Studio. The roster took comm's global listing filtered by `projectPath === cwd`: comm lists every persisted session (blank New Session rows, archived chats) and the bar resolved its project once at window start, so the chips were dead chats named after the folder, for whichever project was current when the window loaded, every one of them labelled Disconnected because `chipStateOf` read `running: false` as broken. `Askbar.module.css` held 35 literal colours (`#FFFFFF`, `#111111`, `#DDDFE3`…), so the bar stayed white in the dark scheme beside a sidebar painted with `--dsw-specific-sidebar-fill`, and drew the brand mark at 44px where the sidebar draws it at 58.

## Decision

**The window is movable and remembers its place per display.** `movable: true`; the bar's `.bar` is `-webkit-app-region: drag` with every button, field and dialog opted out. `askbarPlacement` (pure) chooses the bounds: the stored `askbarPosition` `{ displayId, x, y }` when that display is attached (x clamped into its work area, full height), else the docked column by `askbarSide` on the display under the cursor. `show()` places before it shows on both paths, including the deferred `ready-to-show` one; the after-show re-placement stays as the cascade fallback. `moved` (macOS, once per drag) and a settled `move` stream (Windows and Linux) write the position through the desktop settings scope; a move that echoes the window's own last placement writes nothing, which is what keeps the settings echo (`settings/updated` → `refreshAskbar` → `place`) from looping. The setting is `null` or a full record: a half record fails the load rather than place the bar off screen.

**The Studio leads, with the owl.** The Studio entry sits directly under the brand mark and project cell, labelled Studio, aria-label "Studio — open it in the main window". Its mark is `@idealize/skin`'s new `OWL_FRAME_STILL` (the splash run cycle's first frame, exported beside `SPLASH_FRAMES`), served by the askbar host as `/idealize/askbar/owl.webp` and drawn 30px tall inside a 36px rounded tile on `bg-layer-1`. The client bundle imports no cross-package value, which is the bundle purity rule. The panel foot reads Open the Studio.

**The bar shows the sidebar's rows.** `selectRoster` (client, pure) applies the sidebar's rule over the session and workspace stores: the current session's workspace, its `sessionIds` in stored order, without archived, subagent or provisional rows (a blank chat is provisional; a blank terminal stays, since the sidebar lists it under its agent's name and comm names it — the landing-15 walk found a project whose only listed chats were a New chat and a named terminal, and the bar showed nothing); without a current session, the most recently touched accounted session's workspace, then the first workspace; a stray current session shows its folder's ungrouped sessions. The plugin subscribes to both stores and hands each new selection to the store, which refreshes at once and drops the old roster when the project changes. The roster route gained `sessions=<id,id>`: the host joins comm's rows by id in that order, and a session comm does not list (the Studio chat) contributes no chip. Without the parameter the old `projectPath` filter applies.

**`idle` replaces `disconnected`, and attention outranks it.** The fold now reads wrong, then needs-input, then idle when nothing runs, then working, then ready. comm's `running` is `agent.status === 'running'`, false for a loaded agent between turns and for a cold session alike; both are chats with nothing running, which is idle (comm's own status word), while an owed answer is owed whether or not the agent is loaded. Disconnected was reserved for a host that cannot be reached, which is the bar's error state rather than any chip's.

**Tokens throughout.** Every colour in `Askbar.module.css` is a theme token: the sidebar fill painted over `bg-base` (a transparent fill from an appearance surface shows the ground, as the main sidebar does), label tokens for ink, `border-l*` for rules, the brand accent for needs-input and unread, error for wrong and listening, success for presence. `BrandMark` renders at 58 under the sidebar's 16px top inset. `tests/askbar-css.spec.ts` reads the sheet and fails on any literal colour. Copy moved to `src/client/locales.ts` (`idealize-askbar`, en and zh), delivered as the `t` seat by declaring `locale` on the root registration.

## Alternatives considered

**Filter client-side after fetching the project's comm rows.** Membership is by workspace account, `projectPath` by session header; a session accounted under a workspace whose header folder differs would vanish. Sending the ids lets the host cover exactly the sidebar's rows.

**Keep `disconnected` for `running: false`.** comm exposes no liveness apart from `running`, so the label could not tell a loaded idle agent from a cold session, and read both as faults.

**Inline the owl frame into the client bundle.** A value import from `@idealize/skin` breaks bundle purity, and the frame is 190×210 WebP that every window would carry; one immutable route serves it once.

## Consequences

The floating root carries `data-idealize-surface="sessions"`, so an appearance setting for the sessions column paints the bar the way it paints the sidebar (without it the bar painted the bare ground while the sidebar took the surface fill). The desktop settings schema carries `askbarPosition`; the tray is untouched. Walk checks for `landing-walk-proof.mjs` (the Askbar window is the page target whose URL carries `dsh-desktop-mode=askbar`): the bar's first child after the project cell is the button labelled "Studio — open it in the main window" and it contains an `img` whose `src` ends `/idealize/askbar/owl.webp`; no element reads "Group chat"; the computed `background-color` of `.bar` equals the main window sidebar's (`getComputedStyle(sidebar).backgroundColor`) in both schemes; the brand `img` is 58×58; `getComputedStyle(bar).webkitAppRegion === 'drag'` and every `button` inside reads `no-drag`; the chip ids under `[role=list]` equal the main sidebar's visible session ids for the current workspace; after `screen`-driving a drag (or `setBounds` plus an emitted `moved`) the settings file holds `askbarPosition` with the display id, and a collapse after `expand` lands the window at that x before its first paint; a chip whose session is not running reads "Idle", never "Disconnected". Tests: `askbar/tests/{selection,roster,chip-state,routes,askbar-css}.spec.ts`, `askbar/tests/{apply,askbar-root,askbar-store,panel}.client.spec.ts(x)`, desktop `tests/askbar-window.spec.ts`, `tests/plugin.spec.ts`.
