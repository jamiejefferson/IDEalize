# Agent Note: The appearance package gets a host face, so a clean checkout builds

Status: implemented

## Problem

Every CI job on the private harness repo and every Vercel build failed the same way once GitHub Actions ran again on 16 Sep 2026: `tsc -b tsconfig.host.json` reported `Cannot find module '@deepseek-ai/dsh-commands/remote'` from `packages/api/remotes/src/client/index.ts`. Those `./remote` entries are generated by the typert tsdown plugin during the host bundle, after the host typecheck, so nothing in the host face may reach the client-face project that imports them. `@idealize/skin` (host) imports `deriveTokens`, `presetPalette` and `tokenDeclarations` from `@idealize/appearance`, whose single `tsconfig.json` extended the client base and referenced `client/runtime` and the other client projects, so the host build pulled in the whole client face. Local builds passed only because an earlier client build had left the generated files in `lib/`.

## Decision

`@idealize/appearance` splits into `tsconfig.host.json` (the token derivation, presets, surface CSS, fonts, settings, the host plugin and its invariant, extending the host base) and `tsconfig.client.json` (`src/client/**` and the CSS module declaration, extending the client base and referencing the host face), with `tsconfig.json` as the aggregate, the layout `@idealize/artefacts` already uses. `skin` references the host face; the root host aggregate lists the host face and the root client aggregate lists the client face.

## Alternatives considered

A separate tokens package: correct too, but a new package's README, invariant and gate rows for code that is already face-neutral. Dropping the project reference and relying on `paths`: TS6307, a composite project cannot compile a file outside its own file list.

## Consequences

The host face reaches no client-face project (checked by walking the reference graph); a clean clone's `npm run build:lib:host` passes before any client build. The pre-push typecheck and CI now agree with a fresh checkout. The same workflow change makes the CI check jobs run on a push to `main`, replaces upstream's larger-runner labels with hosted runners where no self-hosted pool is configured, and leaves the real-API e2e suite to a manual run.

## Evidence

Clean clone in the session scratchpad: `pnpm install --frozen-lockfile && pnpm run build` failed at the host typecheck before the change and passes after it; CI run on the commit that carries it.
