# @idealize/ui-gallery

The media grid, and the two spaces that render it: an `Images` entry (`gallery`, order 6) and a `Video` entry (`motion`, order 8) in the conversation view ring, each showing what this chat has generated of its own kind. The ring renders no tab row; a chat lands in one of them because it was launched there, and stays for its life.

One Definition folds every generation this chat ran, whatever it made, and each entry filters that one row source to its kind — `image` for Images, `video` for Video — so a chat sees its own work and only the kind of work the space is for (JJ, 4 Sep 2026: the galleries for sound, image and video are all chat-specific). `@idealize/ui-soundstage` reads the same rows for `audio`. The files themselves are written to the project folder; the chat is where they are seen.

The view renders a grid of tiles, newest first, one per committed artefact, 320px or wider with a 16px gap: an image, or a silent video preview behind a play glyph, loaded from `@idealize/artefacts`' loopback route `GET /idealize/artefacts/raw?id=`, covering a 4:3 frame (the whole picture waits for the enlarged view), with the prompt as the tile's accessible name and nothing else visible on the tile at rest. Hovering or focusing a tile shows **Reveal**, which opens the tool rail's Files pane on the file (the `idealize:reveal-artefact` document event from `@idealize/artefacts`, carrying the artefact's project-relative path; `@idealize/ui-bar` resolves it against the chat's project and lights the row), beside **Keep** or **Archive**; at rest those controls are `visibility: hidden` with no pointer events, and a device with no pointer to hover with (`@media (hover: none)`) shows them always. Clicking a tile enlarges it: the image at full size, or the video in its native player with autoplay, beside its prompt, media type, byte size, aspect and project-relative file path, with the same three verbs and **Close** in a column that scrolls when the copy runs past the sheet (Escape closes; so does clicking the backdrop, and a click on the player stays inside). **Archive** moves the file into the archive subfolder (`Images/Archive/…` by default) and the tile into a collapsed **Archived (n)** fold below the grid; **Keep** brings both back.

Between the message and the tile, the grid reads like a chat (JJ, 8 Sep 2026: posting a message "looks like it's not working"). A row spanning the grid shows the person's prompt, clamped to three lines, beside the state of the work: a spinner and **Thinking…** from the moment the turn opens, **Generating…** once the model has called a generation tool, and when a turn ends without one, the model's last reply in the prompt's place (or "Nothing was generated this turn." / "Stopped." when it left no text). The finished tile takes the row's place. A failed task shows the provider's own reported cause and a **Retry** that resubmits the same prompt and settings as a new message on the same chat (MOD-05). A chat that has generated nothing and has no turn to show explains what fills it.

On the composer's tool row, while the chat sits on Images, Video or the Sound Stage, the mode adds the generation settings strip: one compact control per setting the space's model takes (a select for a choice, a number input for a number, a checkbox for a switch), and on Images the number of images one prompt asks for.

## How it reads the session

The package registers three conversation Definitions and one `gallery` view target. `gallery-generation` keeps one Context per generation call and folds five records the host already writes:

| Event | Effect on the row |
|---|---|
| `tool/call` naming `generate_image` / `generate_video` / `generate_audio` | starts the row; the raw arguments carry the prompt, `aspect`, and `duration_s`; the event's `turn` joins it to its turn |
| `artefact/created` whose `sourceTask.callId` names that call | appends the committed artefact and settles the row as done |
| `artefact/failed` for that call | settles the row as failed with the adapter's provider cause |
| a failing `tool/result` for that call | settles a row whose call never reached a provider (an unavailable media preset fails before any adapter runs) |
| `artefact/disposition` whose `sourceTask.callId` names that call | marks the artefact archived or kept and follows its moved path |

The first cause recorded wins, so the generic tool text never overwrites the provider's own words.

`gallery-turn` keeps one Context per turn: `turn/start` opens it `thinking`; a generation `tool/call` in that turn moves it to `generating` and records the call id; `assistant/message` keeps the model's last text; `turn/end` settles it `generated` when a generation call happened and `no-generation` otherwise, with the end reason. `gallery-prompt` keeps one Context per `user/message` whose source is the person (injected context is not a prompt), carrying the text and log position. A `user/message` carries no turn number, so the target's builder joins each prompt to the turn whose `turn/start` precedes it (`joinPrompts`), and the snapshot publishes `rows` and `turns`, both newest first. The views render the turns still `thinking` or ended with `no-generation`; a turn that reached a generation call is told by its row.

The mode adds **no session event type** and needs no host half: everything it displays is already in the log and already in the read vocabulary, and Keep / Archive posts to `@idealize/artefacts`' `POST /idealize/artefacts/disposition`, whose reply the store records as the `artefact/disposition` event the grid then folds. The host entry exists only so the Loader can mount the package.

## The generation settings strip and the message it writes

The strip (`GenerationSettings`, registered on `conversation.input.left` as `idealize-gallery-settings`) renders while the chat's view ring sits on `gallery`, `motion` or `soundstage`. Its fields come from `GET /idealize/generate/inputs?space=<view id>`, which answers `{ model, fields }`: the active model's inputs as `{ name, label, kind: 'enum', values, default? }`, `{ name, label, kind: 'number', integer, min?, max?, default? }` or `{ name, label, kind: 'boolean', default? }`, with `prompt`, plain strings and provider-internal fields left out. An enum renders a select; a number renders a number input carrying the model's bounds, stepping by one for an integer, with the default as placeholder and a seconds unit after a `duration`; a boolean renders a checkbox followed by its word and writes `name true` or `name false` when moved off its default. When the tool row has less room than the labelled strip asks for, the strip carries `data-gen-settings-compact` and stacks each label above its control in small type, and the switches, which share one box (`data-gen-switches`) after the other controls, stack into a column, so every setting keeps its word at every width. Each control's label sits on `data-gen-setting-kind`. The strip fetches when the view changes and again on the document event `idealize:brains-changed`, which the Brains pane raises after a model change, so a new model's settings appear without a reload. Known field names take their label from this package's dictionary (Aspect, Duration or Length, Resolution); any other field shows the label the route sent. A field with no schema default starts unset (shown as `–`) so a required input the model has not been told is visible before the send fails.

When the route is absent or the service publishes no schema (`fields: []`), each space falls back to its own vocabulary: Images offers Aspect (auto, 1:1, 4:3, 3:2, 16:9, 9:16); Video offers Duration (unset, 5, 8, 10 seconds) and Aspect (auto, 16:9, 9:16, 1:1); the Sound Stage offers Length (auto, 5, 15, 30 seconds). Images always adds the Count control (1 to 4) beside the fields, on schema and fallback alike.

The composer exposes no pre-submit seam a plugin can occupy, so a control that must reach the model states itself in the message the user sends. The strip maintains one trailing bracketed tag on the draft, `[part, part, …]`, in which a field writes `<name> <value>` (the field's own name, except `aspect_ratio` writes `aspect`; the value is one token without commas) and the count writes `<N> images`, in strip order with the count last: `[aspect 16:9, 3 images]` on Images, `[duration 8, aspect 9:16]` on Video, `[duration 5, resolution 720p]` for a model whose schema names those fields, `[duration 15]` on the Sound Stage. The generation tool maps `aspect` to its aspect argument, `duration N` to `duration_s`, `N images` to the count and every other part to the model option of that name. A field at its default writes no part and a strip with no parts writes no tag, so a user who never touches the strip never sees one, and the tag stays ordinary editable text. Reading the draft back, a trailing bracket whose every part names a field of the current strip (or a count, on Images) is the tag; any other trailing bracket is the user's own text and is left alone. The tag adds at most about a dozen tokens to a user message.

For the packaged walk the DOM carries `data-gen-settings-space="<view id>"` on the strip root (plus `data-gallery-settings` on Images), `data-gen-setting="<field name>"` on every select (`count` for the count), and `data-gallery-aspect` / `data-gallery-count` on the aspect and count selects wherever they render. On the grid: `data-gallery-tile="done|running|failed"`, `data-gallery-actions` on a tile's hover controls, `data-gallery-play` on a video preview's glyph, `data-gallery-turn="thinking|no-generation"` with `data-gallery-prompt`, `data-gallery-working="thinking|generating"` and `data-gallery-reply` on the chat rows, and in the enlarged view `data-gallery-details`, `data-gallery-detail-actions` and `data-gallery-player` on the native video player.

The Retry button does not use the strip: it resubmits the settings the failed task itself ran with, so a retry asks for exactly what the original asked for.

No model or provider identifier appears anywhere in this package. Routing is the media preset's job, and the enlarged view names only the media type, byte size, aspect and file path the artefact record carries.

## Rendered proofs

`packages/idealize/ui-gallery/proof/gallery-proof.mts` boots the real composition (storage, sessions, workspaces, the webserver, `@idealize/artefacts`, `@idealize/generate`, `@idealize/gen-fixture`, and `@idealize/gen-tools`), runs the real `generate_image` tool through the real tool registry into four project chats, then renders this package's own view over the session logs those runs left, at 1280x840 in both themes:

```sh
OUT=.idealize/proof pnpm exec tsx packages/idealize/ui-gallery/proof/gallery-proof.mts
```

It writes `gallery-{populated,enlarged,archived,generating,error,empty,media-images,media-video}-{light,dark}.png` and fails the run unless every thumbnail decoded off `GET /idealize/artefacts/raw?id=`, the enlarged view names an `Images/<yyyy-mm-dd>_<id8>.png` path, Archive through the real disposition route moves the file under `Images/Archive` and the tile into the fold and Keep moves both back, the in-flight row is present, the failed row carries the provider's cause and one Retry, and the composer controls write `[aspect 16:9, 3 images]` into the draft. One further chat generates an image, a clip and a sound, and is rendered through both entries: Images must show its image alone and Video its clip alone, the clip must load from the raw route, the count control must be absent from the Video composer while a duration select is present, and the Video empty state must name video rather than images. Alongside `@idealize/gen-fixture`'s own artefact, the run registers a proof-only backend on the same `ctx.generation` seam for a full-size PNG and for the never-settling and always-refusing models the in-flight and failure proofs need; nothing writes an artefact record by hand.

## Model Experience

Indirectly, through the trailing settings tag the strip writes into the draft (`[aspect 16:9, 3 images]`, `[duration 8, aspect 9:16]`), which reaches the model as ordinary user-message text; the view registers no tool, prompt contribution or session event of its own.

#### KV Cache effect

Independent: the tag is at most about a dozen tokens of user-message text, present only when a control is off its default, and appended after the reusable prefix like any user turn. Reading the log, the artefact store and the inputs route changes no request.

## Known Limitations and Deferred Work

- **The settings controls reach the model through the draft, not through a submission hook.** `ui-conversation`'s input machine routes every send through a private default sink with no plugin seam, and the fork discipline in `FORK.md` keeps IDEalize out of that file. If a pre-submit contribution seam lands upstream, the tag mechanism should move behind it so the draft stays purely the user's text.
- **A generation whose `tool/call` fell out of the loaded window renders no row.** The Definition starts rows at the call, so paging further back is what recovers older tiles; the grid does not fetch artefact records independently of the log.
- **The grid shows this chat, not the project.** `ctx.artefacts` publishes no HTTP listing route, so a per-project view would need one; this package deliberately adds none and reads the session log instead. A project-wide view of everything a project has generated would need one media-type-parameterised listing on `@idealize/artefacts`, not a private route here.
- **A schema value the tool cannot parse reaches the model verbatim.** The strip writes the enum value the route sent (`duration 5`); a model whose duration enum is spelled `5s` writes `duration 5s`, which the tool's `duration_s` mapping does not read as a number.
- **Generation progress is a spinner, not the provider's queue position.** The queue adapter reports `queued (position n)` through the seam's progress sink, but `@idealize/gen-tools` passes no sink and the log carries no progress event; adding one means a new `SessionEventMap` member with `ignorable: true` and a doc-sync update, deferred until the walk shows the spinner is not enough.
- **A turn's prompt is the first user message after its start.** A steering message sent mid-turn is not shown; the turn row shows what opened it.
- **Archive moves, never deletes.** Deleting a generated file is left to the Finder or the Files view; a delete verdict would need its own confirmation and its own disposition value.
- **The fallback vocabularies are fixed.** A space whose model publishes no schema offers the values listed above; any other value goes in the prompt as prose, or into the tag by hand (a typed value the menu lacks is shown as an extra option).
