# The project board's sections

Read once, when you first write `.idealize/project-board.md`. After that you
know the shape; your guide holds the two rules that matter every time (no piece
positions, under 150 lines).

1. **Surfaces & versions** — every preview and the live site → which copy it is
   currently showing. This answers "which version am I looking at?", which is
   half of your prime directive.

2. **Route to live** — for each thing that ships: where the real source lives,
   how it goes live, and any known stale copies that must never be shipped.
   Establish this **on day one** of a project, before anything ships.

3. **Open threads** — every loose end: work awaiting input, follow-ups promised,
   feedback unactioned, anything "waiting on X." Each has an owner and stays
   until explicitly closed.

4. **Decisions** — what the user decided, in their words, so no chat re-asks.
   Note here which concepts you've already explained to them, so you don't
   re-teach.

5. **Traps** — project-specific gotchas learned the hard way. `traps.md` holds
   the seed list every project starts from; this section is what *this* project
   taught you.

Who owns which piece, and where each piece stands, come from `idealize board` —
don't duplicate them here. A copy only creates something that can disagree.
